## 1. Architecture in one breath

A **Google Sheet is the single source of truth.** A **single-file HTML dashboard** (`index.html`) is a read/write *view* of it; it holds no authoritative state. A **Google Apps Script web app** (`apps_script.gs`) is the only thing that touches the sheet: `doGet` serves reads, `doPost` serves writes, both returning JSON. The dashboard talks to the deployed Web App URL (`SCRIPT_URL`) via `fetch`. `SCRIPT_URL` is loaded from a **gitignored `config.js`** (`window.CONFIG.SCRIPT_URL`); a saved URL in `localStorage['fin_url']` overrides it, and when neither is present the boot path shows the setup screen.

```
Google Sheet  ◄──►  apps_script.gs (Web App: doGet reads / doPost writes)  ◄──fetch──►  index.html (browser)
   (truth)            tests.gs · debug.gs · migrate.gs live in same Apps Script project
```

**Source of truth for code + docs: the public GitHub repo `bencoscia/finance-dashboard`.** `index.html` is served from **GitHub Pages** off that repo. The backend lives in a separate Apps Script project; the repo's `.gs` files are reference copies, not the live backend. Claude reads the live files via `raw.githubusercontent.com` (CDN-cached ~5 min); pushes are manual — you commit. `config.js` (the `SCRIPT_URL` bearer secret) is gitignored and never in the repo.

## 3. Invariants — do not violate

1. **The Sheet is truth.** The dashboard never invents state; it reads from / writes to the Sheet. Client caches (`allData`, `nwData`, `loanData`, `mortgageData`) are views and must be invalidated when a write changes them.
2. **Zero inline `on*=` attributes in HTML.** No `onclick="…"` (or any `on…=`) in rendered markup. Interactions go through `data-action`/`data-args` + the document-level `ACTION_MAP` dispatcher, or through `.onclick`/`.oninput` **property closures**. The JS-string-inside-HTML-attribute escaping bug class caused three outages and is now structurally extinct — do not reintroduce it. (`.onclick`/`.oninput` property assignments are *allowed* — real closures, never the hazard; audit.md's count of "seven" is stale, it's ~12 now *(verify)*.)
3. **Dual-router rule.** A read action must be registered in **both** dispatchers in `apps_script.gs`: the `doGet` chain (~L137) **and** the unified action chain (~L93). A write goes in `doPost` (~L146) and, if it mutates money or rows, is wrapped in `_withIdem`.
4. **No silent staleness.** Any value interpolated into already-rendered HTML must be re-rendered by every write that changes it; cross-tab caches affecting net worth must be nulled on relevant writes.
5. **Protan-safe visuals (Ben is protanopic).** Never encode meaning by hue alone. Separate series by **lightness, dash pattern, axis, shape, and a text label** — at least two non-color channels, always.
6. **`.gs` is ES5 + ASCII only.** `var`/`function(){}`, no arrow fns, no template literals, no non-ASCII characters. `index.html` JS follows the same `var`/`function`/string-concatenation style; no template literals in rendered HTML strings.
7. **Chart.js discipline.** Destroy the instance before re-rendering (`if(cX){cX.destroy();cX=null;}`). There is **no time-scale adapter** loaded — use category-string labels + `maxTicksLimit`. Chart.js cannot read CSS custom properties — resolve them with `getComputedStyle` (helper: `cssv(name, fallback)`).
8. **A write returns the new truth; one function applies it (UX_SPEC §2, 2026-11).** Every write that can move a balance or a monthly total ends with `afterWrite(res)` -- never its own `apiFetch` of `quick`/`cardBalances`. `applyFresh(fresh)` is the only code that assigns `allData.cardBalances`/`monthly`/`months` after a write and re-renders the tiles + Budget tab. Until the backend attaches `res.fresh` (UX_SPEC Phase 1B, not yet deployed) `afterWrite` falls back to `quick` + `cardBalances` **in parallel, coalesced** (a write during an in-flight refresh marks it dirty; exactly one more runs after). A failed refresh shows an error banner -- never silent. `quickRefresh`/`refreshCardBalances` are deleted; grep must stay at zero.
9. **Bump cache versions on shape change.** Change a cached payload's fields → bump the matching `CACHE_VERSION` (`monthly_v3`) or `CARD_CACHE_VERSION` (`cards_v1`).

## 4. Traps / failure modes (each has bitten before)

- **Deployment skew.** "New deployment" mints a *new URL that serves the old code forever*. Always **pencil-edit the existing deployment → New version** (same URL). Symptom of a stale deploy: `Unknown action: <x>` from a read/write you just added.
- **Dual-router drift.** Forgetting to add a read to *both* chains (Invariant 3) → works via one entry point, fails via the other.
- **Interpolated-UI staleness.** A write updates the Sheet but not the baked-in HTML/caches → the tab shows old numbers until reload.
- **`--blue` is green.** `--blue` = `--green` = `#1E5C46`. The actual blue is `--c2` `#3E6B8F`. Misnamed token — read §6 before picking colors.
- **Mortgage balance — one source (resolved 2026-06-16).** The `Loans!M–W` ledger is the source of truth; `Physical Assets!B8` is now a **formula** mirroring its current balance — `=XLOOKUP(TRUE, Loans!N8:N400, Loans!O8:O400, "NO PAID ROW", 0, -1)` (balance on the last `TRUE`-flagged row). Net worth reads B8, the mortgage tab reads the ledger, and they can't drift because B8 derives from the ledger. The one manual input is the **col-N paid flag** — tick it the month a payment posts. **Do not overtype B8 with a literal** — that re-creates the old hand-maintained duplicate (the ~$343 / one-month drift). Two Sheets gotchas: the Excel `LOOKUP(2,1/(…))` last-match idiom returns `#N/A` here — use XLOOKUP; and bound the range to the schedule’s last row so a stray `TRUE` in another loan block below can’t be matched (XLOOKUP `-1` searches bottom-up). If B8 ever reads `NO PAID ROW`, net worth silently books $0 mortgage.
- **Home Screen app = separate browser profile (iOS).** The installed app does **not** share `localStorage` with Safari: first launch shows the setup screen (paste `SCRIPT_URL` again), and `hsa_calc_v2`, the HSA filter, split tax rate and pending-txn flags start empty. Changing any Home Screen head tag (icon, title, status-bar style) does nothing for an existing icon — delete it and re-add from Safari, per device. Standalone and safe-area behaviour can't be verified headless; only layout at 390×844 can.
- **`config.js` isn't served on Pages.** It's gitignored, so on GitHub Pages `window.CONFIG` is undefined and `SCRIPT_URL` is empty — by design. The setup screen is the Pages onboarding (paste the URL once → saved to that browser's `localStorage['fin_url']`). `bootDashboard()` **must** fall back to `showSetup()` when there's no URL; a missing `else` there once left Pages blank-white. Works locally because `config.js` is present.
- **No client-side password gate.** One was added and removed — it's theater: page source (hence any hash) is world-readable on Pages, and `SCRIPT_URL`, not the gate, protects the data. Don't reintroduce. Real access control = `SCRIPT_URL` secrecy now, a server-validated token later (§9).
- **`SCRIPT_URL` precedence:** `localStorage['fin_url']` (set via setup) wins over `config.js`. A stale saved URL silently overrides a fresh `config.js` — clear it via the setup screen if you repoint.
- **HSA double-reimbursement (cardinal risk).** Paying out a receipt twice is an over-withdrawal the IRS can claw back. Two layers: `reimburseReceipt` is `_withIdem`-wrapped **and** writes `reimbursed_amount` as an **absolute** value (a retry writes the same number, never adds), plus a server `_reimburseGuard` rejecting `> amount`, negative, `funding=HSA`, and pre-establishment rows. The UI "Reimburse to total ($)" field is the absolute total, not an increment — keep it so.
- **HSA establishment gate.** Only expenses on/after `Config!hsa_established` qualify; earlier rows are flagged ⚠ and excluded from every total. **Blank `hsa_established` → gate OFF** (nothing disqualified) and the tab shows a ⚠ banner — set it or totals overstate.
- **HSA balance is `B1`, blank ≠ 0.** `HSA Receipts!B1` (manual) is the only balance source; **blank → `null` → renders "—", never `$0`**, and `reimbursableNow`/`strandedEntitlement` stay `null` (not computed against 0). HSA is **not** in net worth yet (§9). Receipts store a **Drive link**, never an embedded image.
- **`cfg()` cache is shape-versioned (`CFG_CACHE_KEY`, 5-min TTL) — bump it on every Config-shape change, not just `getNetWorth`'s.** Adding `hsaEstablished` without bumping `cfg_v1`→`cfg_v2` meant a config cached moments before the redeploy kept serving the old shape (missing the field) for up to 5 min — surfaced as "No HSA establishment date set" even with the sheet row correct. Same root cause as the documented `nw_v1`→`nw_v3` incident (§ bug class 2), now also true of `cfg()`. (Bumped again to `cfg_v3` for `hsaReceiptFolder`, then **`cfg_v4`** for `hsaDeductible`/`hsaContribLimit`/`hsaDeductibleResetMonth`.) `testConfigParsing` asserts the round-trips, but it can't catch a forgotten version bump — that's a manual checklist item.
- **`HSA_CACHE_VERSION`** has climbed `hsa_v1→v6` (v2 `needsReview`, v3 `planYear`, v4 `contribRows`, **v5 date-aware balance** = `inflowsSince`/`outflowsSince` + `computedBalance` now projects B1 forward; **v6** rows carry `notes`, tombstones excluded). Any cached-payload shape change needs the bump or stale reads persist up to the TTL.
- **Balance reconciliation is done AS OF the B1 anchor date (`balanceAsOf`/B2), not "now."** Earlier it compared an all-time reconstruction against a possibly-stale B1, so spending logged *after* B2 inflated `drift` — a $345 drift that was really $312 of post-B2 card spend + $32 interest. Fix: `_hsaPlanYear` splits inflows/outflows by B2, reconciles `computedThruB2` vs B1 (drift ≈ unlogged interest only), and the displayed balance projects B1 forward by since-B2 activity (`computedBalance = B1 + inflowsSince − outflowsSince`). **Keep B2 current when you update B1**, or the "since" projection grows. Card spend counts as outflow even for `needs_review` drafts (cash left regardless of qualification); the deductible total excludes drafts.
- **Contributions-reader gotcha (drift ≈ total contributions).** If the reconciled balance's drift comes out ≈ your lifetime contributions, `inflows` is landing at $0: the `HSA Contributions` sheet is found but every row is skipped. Algebra: `B1 = contrib + interest − spend`, so with `inflows=0`, `drift = B1 + spend = contrib + interest`. `_hsaReadContributions` now locates the **amount** column by header name (robust to column reorder) and strips `$`/commas (text-formatted amounts), and `planYear.contribRows` lets the UI show "sheet found, 0 amounts read" instead of a garbage negative balance.
- **The plan-year balance is a reconciliation, not a source of truth.** Fidelity (`B1`) is authoritative; `_hsaPlanYear` reconstructs a balance from logged inflows (the `HSA Contributions` sheet) minus outflows (card spend + reimbursements) and reports `drift = B1 − computed`. Small drift (≤ max($50, 2%)) is expected and ≈ unlogged FDRXX interest (interest is deliberately **not** logged, to keep the contributions sheet clean); large drift means activity is unlogged — re-import the Fidelity export. **Card spend counts as a balance outflow even for `needs_review` drafts** (cash left the account regardless of qualification), whereas the *deductible* total excludes drafts — the two sums intentionally differ. Interest, if ever logged, is a balance inflow but does **not** count toward the contribution limit (limit gauge = employee+employer only).
- **`needs_review` drafts are deliberately invisible to totals.** A scanned-but-malformed receipt is present (and visible, sorted to top with ✎) but contributes **$0** to `unreimbursed`/`totalSubstantiated`/the pool until you confirm it via Edit. Intentional (don't trust unverified data) — but it means "I scanned it and the pool didn't move" is expected, not a bug.
- **The HSA projection is a two-engine, nominal-dollar model.** Engine 1 (recurring tax avoided = spend×(tc+f)) is certain and market-independent; Engine 2 (the hoard) is the only market-dependent part and only matters on receipts you *keep* (don't reimburse). Don't conflate them, and don't read the old "$8k/yr for 30 yrs, hold forever" framing back in — that was ~80× too high because it used the contribution limit instead of the real claim rate and never reimbursed. `hsaProjCompute` is pure and cross-checked offline; at the demo inputs ($2,800/$500/20/30) it must produce Engine 1 $1,054/yr and Engine 2 HSA $43,145 / IRA $31,078 / taxable $22,469. Spend/hoard auto-fill from the ledger TTM; a user override (saved in `localStorage['hsa_calc_v2']`) wins over the TTM prefill.
- **Folder scan: filename is load-bearing data.** `scanHsaFolder` parses `DATE~provider~amount.pdf` into the row's date/provider/amount — a filename typo becomes a wrong ledger entry. `_parseReceiptName` is strict and **skips + reports** anything off-pattern rather than guessing. Delimiter is `~` (provider may contain spaces/underscores; it may **not** contain `~`).
- **HSA duplicate detection (2026-10) — `_hsaFindDup`, one rule for both entry orders.** Before this, the scan deduped on col-L `fileId` only, so a receipt entered via Quick Add (HSA-eligible draft) *and* scanned became two rows in **either** order (verified against the old code). Now, per scanned file: (1) **file** match — col L, *or* an existing row's receipt link that points at this Drive file (`_hsaDriveId` parses `/d/<id>` and `?id=`) → skip, backfilling col L; deleted rows count, so a deleted receipt is never resurrected; (2) **exact** — same date + same amount, on a row not tied to another file → attach the file to that row (col L, col H if blank), no new row; (3) **near** — same amount within `HSA_DUP_WINDOW_DAYS` (7) → imported as a `needs_review` draft noted "Possible duplicate of #id". A txn-originated draft (`addHsaReceipt` with `needsReview` and no `sourceFileId`) runs the same check: exact → **no row**, returns `duplicateOf`; near → created + noted. Known blind spot: txn date ≠ service date by more than 7 days and no Drive link pasted → no match. Pasting the Drive link into the draft before scanning is the deterministic fix. Auto-created rows are `funding=OOP` with blank category/description to fill in.
- **Delete is a tombstone (col N `deleted`=TRUE), never a row removal.** A hard-deleted scanned row loses its col-L fileId and the next scan re-imports the file; a removed max-id row would let `max+1` reuse its id. **Don't delete HSA rows in the Sheet — use the dashboard (or type TRUE in col N).** `deleteHsaReceipt` refuses a row with `reimbursed_amount > 0` (a withdrawal record — zero it via Reimburse first); `reimburseReceipt`/`updateHsaReceipt`/`approveHsaReceipt` refuse tombstones; `getHsa` filters them before every total.
- **Scan no longer nests the script lock.** It used to call `addHsaReceipt`, whose `releaseLock()` released the scan's own (reentrant) lock after the first file. Now `_hsaPrepRow` (validate) + `_hsaAppendRow` (write; caller holds the lock).
- **Receipt upload: two files = two rows.** The scan dedups on Drive fileId, and content-dedup skips rows already linked to a file, so two uploaded copies of one receipt both become rows. Hence `uploadHsaReceipt` is `_withIdem`-wrapped (apiPost's auto-retry reuses the key) and trashes its file on any placement failure. A *manual* re-upload after an uncertain network error bypasses both -- refresh the HSA tab first, as with every write.
- **Receipt photos never reach the server as images.** The client decodes the camera image (HEIC included, on iOS Safari), re-encodes JPEG (long edge 2000 px, q 0.82) and wraps it byte-for-byte in a 1-page PDF (`hsaJpegToPdf`, DCTDecode). The folder stays all-PDF and there is no server-side conversion to break. A desktop browser that can't decode HEIC fails loudly in the photo field.
- **`DriveApp` needs the Drive OAuth scope.** Adding the folder scan introduces a new scope; the first `scanHsaFolder` run prompts re-authorization. After deploying, run it once from the editor (or via the button) and approve, or the web app returns an auth error.

- **`ACTION_MAP` bare references receive the click event as their first argument.** `'x': fnX` calls `fnX(e)`. Fine for zero-arg functions and for ones that expect `e` (`showQuickAdd`, `qaSetType`); wrong for anything with real parameters -- `addSplitRow` rendered `[object PointerEvent]` as the new line's description (fixed 2026-09 by wrapping it). **Any function with parameters goes in `ACTION_MAP` as a wrapper closure**, never a bare reference.
- **Card-width `overflow:hidden` silently clips edit controls.** `.var-section` (1/3-width grid card) clipped the gas/grocery edit row's save/cancel cell -- no visible way to save. Now `overflow-x:auto`, edit-row inputs shrink (`width:100%;min-width:0`), and Enter saves / Esc cancels. Prefer scroll over clip on any container holding interactive controls.
- **Transient Apps Script failures (HTTP 404/429/5xx, dropped connections, HTML error page served as 200) -- 2026-09.** Intermittent `Failed: HTTP 404` that a manual refresh cleared. `netWithRetry` now makes 3 attempts (backoff ~0.7 s, ~1.8 s + jitter) for **every GET**, and for a **POST only when it carries an `idemKey`** (server dedup makes it safe). App-level `{error:...}` responses and non-transient statuses (403 etc.) never retry. **A failed POST response is not a failed write**: doPost runs, then redirects to a result URL; a 404 on that hop loses the answer, not the write -- so every exhausted POST error says "it may have saved; refresh to check before retrying". Every failed attempt is logged locally (`localStorage['fin_netlog']`, script id redacted) with the host/path that failed and whether a retry recovered -- run `netLog()` in the console. Diagnosis key: failures at `script.googleusercontent.com/macros/echo` = Google result-cache hiccup (retry is the right fix); at `script.google.com/macros/s/<id>/exec` = the deployment itself (check the saved URL / deployment state); a `/macros/u/N/` path = Google-account routing.
- **Scripted `insertSheet`/`deleteSheet` can time out the whole execution** (extends bug L): each insert triggers full workbook recalculation (~40 sheets, heavy formulas). Do not write functions that create sheets -- create tabs manually and paste headers. `testLedger`'s scratch tab is create-once-then-reuse; pre-create `_TestScratchLedger_` manually to avoid even that first insert.
- **Apps Script editor files can drift from the repo, and a duplicate `doGet`/`doPost` in ANY project file silently overrides the router** (later file wins, no warning; cost half a day 2026-07: a stray `doGet` in the editor's `tests.gs` -- absent from the repo -- swallowed every request with "Unknown action"). When routing behaves impossibly: project-wide search for `function doGet` / `function doPost` (want exactly 1 each), and diff editor files against the repo. `/dev` vs `/exec` discriminates code-vs-deployment: `/dev` always runs the latest saved editor code.

- **DST drift in `daycareSchedule()`.** Its Fridays are built by adding 24h multiples to `DC_LAST_PAID T12:00`, so after the Nov DST change they sit at 11:00 local. Comparing those *instants* to a noon "today" dropped the payment on its own due day (tile jumped to the following payment). Always compare via `dcDay()` (midnight-normalized) and `Math.round` day differences. Fixed 2026-10.

- **Equity: Black-Scholes never enters net worth (2026-11).** Net worth counts only **vested intrinsic** (exercise-and-sell value today), computed by the *Sheet*: `Equity Grants` col J -> `Portfolio Management` row `SDGR Options` (`=SUM('Equity Grants'!J4:J)`) -> `_computeNetWorth`. B-S lives only in the client (`bsCall`), is display-only, and is an upper bound for employee options (no sale, no hedge, forfeiture, ~90-day post-termination window). Don't add it to any total. The server's `_equityRollup` recomputes vested/intrinsic from the raw vest rows purely as a **cross-check** of cols H/J and of the `SDGR Options` cell; disagreements surface as ⚠ lines on the Net Worth tab.
- **Equity #N/A after paste (2026-11).** Formulas pasted into `Equity Grants` before the `Equity Vests` tab existed showed #N/A in Sheets even though the formula text and data were correct (LibreOffice recomputed the same export correctly). Re-entering the formula (click into the formula bar, Enter) is the fix. The #N/A propagates to `SDGR Options` and the Sheet's own `Net worth` total; the dashboard now flags it instead of silently dropping SDGR (next trap).
- **Error-valued Portfolio Management rows used to vanish silently.** `_computeNetWorth` skipped any non-numeric col C, so `SDGR Options = #N/A` dropped SDGR from net worth with no sign. Now any labelled account row whose value starts with `#` is named in `investmentsWarning`. Same fix: the account scan ends at the `Net worth tracker` / `Date` header found by label instead of a fixed 20-row window -- the window had already dropped `Liquid` after the `Max Trump Account` insert, and `SDGR Options` was two inserts from the edge.
- **Equity vest dates and `TODAY()`.** `addEquityGrant` writes noon dates (like HSA) so a spreadsheet/script timezone mismatch can't move a vest a day; the col H formula therefore uses `"<"&(TODAY()+1)`, not `"<="&TODAY()` (which would miss a noon-stamped vest on its own day). Hand-typed rows are midnight and work with either.
- **Equity placeholders count twice.** A grant row with blank type/grant date but the same strike + size as a new grant is treated as the same grant: `addEquityGrant` refuses and says to delete the placeholder row first. Ids = max over **both** sheets + 1, so a new grant never inherits orphan vest rows. Corrections to a saved grant are Sheet edits (no edit endpoint by design).
- **Volatility is an input, not a computation.** GOOGLEFINANCE *historical* data is unreadable from Apps Script (returns #N/A), so realized vol is not auto-computed. `Config!sdgr_vol` is set by hand (implied vol of the longest-dated listed SDGR option); the tab shows a σ±10pt band because deep-OTM long-dated values roughly double between σ 50% and 70%.

## 5. Server reference (`apps_script.gs`)

**Read actions (21)** — registered in both chains, served by `doGet`:
`all · quick · monthly · networth · transactions · fixed · variableEntries · accounts · cardTotals · cardBalances · cardTxns · config · loans · mortgage · hsa · ledgerMonthly · ledgerTxns · ledgerFixed · ledgerTags · ledgerCheckingHistory · equity`

**Write actions (37)** — `doPost` (★ = `_withIdem`-wrapped):
`addTransaction★ · updateTransaction · deleteTransaction · splitTransaction · setFixedPaid · updateFixedCost · updateFixedName · updateLoanBalance★ · makeCardPayment★ · voidLastPayment★ · setSeedBalance · addVariableEntry★ · updateVariableEntry · deleteVariableEntry · makeCheckingEntry★ · saveNetWorthSnapshot★ · logCreditSnapshot★ · addMonth · reimburseReceipt★ · addHsaReceipt★ · scanHsaFolder · updateHsaReceipt★ · approveHsaReceipt★ · deleteHsaReceipt★ · uploadHsaReceipt★ · ledgerAddTxn★ · ledgerUpdateTxn★ · ledgerDeleteTxn★ · ledgerSplitTxn★ · ledgerAddFixed★ · ledgerUpdateFixed★ · ledgerSeedFixedMonth★ · ledgerEnsureQuarterly★ · ledgerAddIncome★ · ledgerSetTags★ · ledgerSetPending★ · addEquityGrant★`

`voidLastPayment★` matters most of the 2026-07 additions: it voids the *most recent* Card Payments row, so a manual retry after a dropped response would void a **second, older payment** silently — the same failure class as the documented double-payment incident. The idemKey makes the auto-retry safe and the cached result makes an immediate manual re-click a no-op. `addMonth` is deliberately not wrapped — it's naturally idempotent (errors if the sheet already exists).

`scanHsaFolder` is **not** `_withIdem`-wrapped — it's idempotent by construction (dedup on Drive `fileId` stored in `HSA Receipts` col L), takes no args (so a future time-trigger can call it directly), and serializes via `LockService`. Reads the Drive folder named in `Config!hsa_receipt_folder` (requires the Drive OAuth scope — first run prompts re-authorization). A malformed filename is imported as a **draft** (`needs_review`, col M) via best-effort parse rather than skipped; only a name with neither a date nor an amount is skipped. `updateHsaReceipt` is the general edit path (fix any field; clears `needs_review`); reimbursed amount/date stay on `reimburseReceipt` so that remains the single money-moving path.

- **`Loans!A4:J25` — student loans.** A origNum, B renum, C type, **D balance (edit target for `updateLoanBalance`)**, E rate, F interest, G principal, H payment due, I new balance, J % of balance. Row 26 totals (D26 balance, F26 interest); H27 avg rate; H28 % grad school.

Ledger rows 8+: M date, N description/paid-flag (`TRUE`=logged actual), O balance, P payment (P&I + escrow), Q interest, R PMI, S property tax, T principal, U equity %. **Row 40 = `Refinance` marker** (its O cell = new rate; interest switches N3→O40 after it). Cost box: W9 initial projected P&I, W10 current projected P&I (`=SUM(Q:Q)+SUM(T:T)`), W11 savings (`=W9-W10`). Read-only in the dashboard via `getMortgageData`. `Physical Assets!B8` mirrors this ledger's current balance (last `TRUE`-flagged row's O) via formula, and is what `_computeNetWorth` reads for the mortgage liability.
- **`Physical Assets`.** B3–B5 home estimates (Redfin/Zillow/realtor), B6 avg valuation, **B8 mortgage balance — formula `=XLOOKUP(TRUE, Loans!N8:N400, Loans!O8:O400, "NO PAID ROW", 0, -1)` deriving the ledger's current-month balance; net-worth source (was hand-typed, now self-maintaining — don't overtype)**, B9/B10 equity $ / %.

- **`Config`.** `key | value | notes`; read by `cfg()`. - **`HSA Contributions` — contribution/inflow log (optional).** `date | amount | type | notes`; header row 1, data **rows 2+**. `type` ∈ `employee`|`employer`|`interest`. Read by `_hsaReadContributions(ss)` → `null` when the sheet is absent (balance/contrib gauges then hide; the deductible tracker still works off receipts alone). Populated by pasting the Fidelity-export backfill and repopulated by re-importing going forward. Feeds `_hsaPlanYear`: contributions+interest are balance inflows; only employee+employer count toward the contribution limit. Kept separate from `HSA Receipts` so that sheet stays a pure expense ledger. Pure metrics tested by `testHsaPlanYear`.
- **Ledger sheets (migration target, new 2026-07)** -- four flat tables, headers row 1, data rows 2+, rows located by stable `id` (col A), appends only, no formulas below the data block. `Txns`: `id | date | month | description | amount | method | category | discretionary | ben | jenna | tags | pending` (col K: comma-separated lowercase, written only by `ledgerSetTags`; add the `tags` header to K1 manually) (col L: review flag TRUE/blank, written only by `ledgerSetPending`, which refuses to write unless L1 = `pending` -- header added by hand; add/update/split write cols A-J only, so K and L survive edits) (`category` in `onetime|groceries|gas|transfer`; `month` is an explicit YYYY-MM assignment -- a July-1 charge can belong to June's books). `Fixed Log`: `id | month | name | source | amount | paid | paid_date`. `Income Log`: `id | month | date | source | amount`. `Variable History`: `month | category | amount` -- **display/TTM-estimation data only, never summed into totals.** THE AGGREGATION RULE (`_ledgerAggregate` in `ledger.gs`, enforced there and only there): every dollar counts exactly once -- txns via their row, fixed via the paid flag; `transfers` (category `transfer` OR any Checking row with amount < 0) are money movement, excluded from both expenses and income; card negatives (cash back/refunds) net against spend; `totalExpenses = (txn sum - transfers) + fixedPaid`. - **`Equity Grants` (2026-11, created by hand).** `B1` = `=GOOGLEFINANCE("SDGR","price")`, `B2` = `=GOOGLEFINANCE("SDGR","tradetime")`; headers **row 3**, data **rows 4+**, located by header name: `id | type | grant_date | expiry_date | strike | granted | exercised | vested | exercisable | intrinsic | notes`. `type` ∈ NSO/ISO/RSU; `granted` = original grant size (= sum of its vest rows); `exercised` = options exercised/sold (RSUs: 0). Per-row formulas (written by `addEquityGrant`; copy down for hand-typed rows): **H** `=IF(A4="","",SUMIFS('Equity Vests'!C:C,'Equity Vests'!A:A,A4,'Equity Vests'!B:B,"<"&(TODAY()+1)))` · **I** `=IF(A4="","",IF(B4="RSU",0,MAX(0,H4-G4)))` (RSUs never exercisable: vested RSUs are ordinary shares already counted elsewhere) · **J** `=IF(A4="","",IF(AND(D4<>"",D4<TODAY()),0,I4*MAX(0,$B$1-E4)))` (0 once expired). **`Portfolio Management!C<SDGR Options row>` = `=SUM('Equity Grants'!J4:J)`** is the only path into net worth.
- **`Equity Vests` (2026-11, created by hand).** Headers row 1: `grant_id | vest_date | shares`; data rows 2+; one row per vest event (paste from NetBenefits or use the dashboard generator). `vest_date` must be a real date (a text date is silently skipped by SUMIFS; the reader reports it).
- **Config equity keys (2026-11, `cfg_v5`).** `sdgr_vol` (fraction or percent; blank/0 → model values hidden), `sdgr_risk_free` (default 0.04), `equity_tax_rate` (marginal rate on spread/RSU income; blank → after-tax hidden; 0 allowed), `option_pte_days` (default 90). Values above 3 (vol) or 1 (rates) are read as percents.
- **`HSA Receipts` — reimbursement-entitlement ledger.** Metadata: **`B1` = current HSA balance (manual; blank→`null`, never 0), `B2` = balance as-of date.** Headers on **row 3**, data **rows 4+**. Cols A–N: A `id` (stable positive int, never reused — `reimburseReceipt`/`updateHsaReceipt` locate rows by id, not position), B `date_incurred`, C `amount`, D `provider`, E `description`, F `category`, G `funding` (`OOP`|`HSA`), H `receipt_link` (Drive URL), I `reimbursed_amount` (**absolute**; written by `reimburseReceipt`), J `reimbursed_date`, K `notes`, L `source_file_id` (Drive fileId when created by the folder scan; blank for manual adds — the dedup key), **M `needs_review` (`TRUE` for a malformed-import or txn-originated draft; blank once confirmed)**, **N `deleted` (`TRUE` = tombstone; see §4)**. Read by `getHsa` → `{established, hsaBalance, balanceAsOf, unreimbursed, reimbursableNow, totalSubstantiated, strandedEntitlement, planYear, rows[]}` where each row carries `needsReview` (col L is internal, not exposed) and `planYear` carries the deductible/contribution/reconciled-balance metrics from `_hsaPlanYear` (see §4). **A `needs_review` draft is excluded from every total until confirmed** (it's unverified data — `_hsaRollups` gives it `status:'needs_review'` and skips it from `unreimbursed`/`totalSubstantiated`); it sorts to the top of the ledger and shows the ✎ glyph. Written by `addHsaReceipt` and `uploadHsaReceipt` (plain append — no formulas below the data block; **id = max existing id + 1 inside a `LockService.getScriptLock()`**; `needsReview:true` relaxes validation so a partial draft can be stored), `reimburseReceipt`, `scanHsaFolder`, and **`updateHsaReceipt`** (the general edit/correction path — validates strictly, writes B–H, and clears col M; reimbursed amount/date are deliberately **not** editable here so `reimburseReceipt` stays the single money-moving path). Folder scan imports PDFs from `Config!hsa_receipt_folder` named **`DATE~provider~amount.pdf`** (delimiter `~`; `_parseReceiptName` is strict). **A name that fails strict parse is salvaged by `_bestEffortReceipt`** (tolerates `~` or `_`, pulls a calendar-valid date via `_isRealDate` and a positive amount, rest → provider) and imported as a `needs_review` draft; only a name with **neither** a date nor an amount is skipped + reported. Pure helpers `_hsaRollups` / `_reimburseGuard` / `_parseReceiptName` / `_bestEffortReceipt` / `_isRealDate` are unit-tested (`testHsa`, `testParseReceiptName`, `testBestEffortReceipt`); `addHsaReceipt` + `updateHsaReceipt` have scratch-sheet integration tests (`testAddHsaReceipt`, `testUpdateHsaReceipt`, sheet `_TestScratchHsa_` — never the live sheet). **Correct any row in-dashboard via the edit modal (✎ Edit on every row); the Sheet remains a valid fallback.**

## 10. Change protocol — update these together

**Add a read endpoint:** write `getX()` → add `action==='x'` to **both** the `doGet` chain and the unified action chain → client `apiFetch(SCRIPT_URL,'x')` → list it in §5 → **redeploy**.

**Add a write endpoint:** write the mutator → add to `doPost` (wrap in `_withIdem` if it touches money/rows; invalidate affected month/card/net-worth caches) → list in §5 → **redeploy**.

**Add a tab:** nav `<button data-tab="x">` → `<div id="tab-x" class="tab-panel">` panel → `if(id==='x') loadX();` in `showTab` → `loadX()` (gated by `isDemo`→`demoX()`) → `renderX()` → `demoX()` → list in §6. Redeploy only if it needs a new read endpoint.

**Add a chart:** declare `var cX=null;` → destroy before re-render → category labels + `cssv()` tokens → at least two non-color channels (Invariant 5) → add to §6 chart list.

**Add a write that moves a balance or monthly total:** end it with `afterWrite(res, '<label>')`; no hand-rolled follow-up GETs (Invariant 8).

**Change a cached payload's fields:** bump the matching `CACHE_VERSION`/`CARD_CACHE_VERSION`.

**Change a sheet schema:** update the reader's column map + dependent formulas + §8 here; verify against a real export before relying on it.

**Frontend change (HTML/CSS/JS):** commit + push → Pages serves it; hard-refresh (CDN ~5 min). No Apps Script redeploy — that's backend-only.

**Add a mobile rule:** put it in the single `@media (max-width:768px)` block near the end of `<style>`; layout-only; hold Invariant 5 (no color-only meaning).

**Before handing over any `.gs` file to paste:** scan all repo `.gs` files for functions that are called but defined nowhere (and for duplicate top-level `function` names). Any undefined hit means the editor holds code the repo lacks -- recover it from Project history first. (2026-10: `_cardStatementBalances`/`_lastCloseDate`, the drawer's Card Payments rows, and checking-history payment dates existed only in the editor's `ledger.gs`; pasting the repo copy deleted them and every load failed with "_cardStatementBalances is not defined". Recovered from version N-1 and committed.)

**Any structural change:** update this file in the same pass and **commit it** — Done isn't done until INDEX, the code, and the Sheet agree.
